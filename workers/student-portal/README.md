## Replay nativo após #704

`npm run test:student-portal-postgres` exige `PORTAL_TEST_DATABASE_URL` apontando exclusivamente para `postgres://<administrador-local>@127.0.0.1:<porta>/portal705_test`, um banco novo e descartável. Recusa destinos remotos e schema Portal já existente. Não faz limpeza automática nem toca produção. O CI usa PostgreSQL 17.6 isolado; o ensaio local usa 18.6. São seis testes de commit pelo adapter postgres.js, rollback, ACL negativos com conexões reais por role, view restrita, função guard do ADM e FK RESTRICT. O executor das migrations do Portal tem CREATEROLE e permissões específicas no banco sintético, sem SUPERUSER/BYPASSRLS.

A primeira tentativa Supabase da migration 0001 foi recusada com 42501: um administrador gerenciado não pode repetir NOSUPERUSER/NOBYPASSRLS em ALTER ROLE. O catálogo confirmou rollback completo (schema e role ausentes). A correção nominal registrada na allowlist #705 conserva CREATE ROLE restrito e recusa role pré-existente administrativa, herdável ou membro de outra role; não tenta rebaixar atributos de superusuário. O replay local corrigido passou com executor não-superusuário. Aplicação remota corrigida e read-after-write por Hyperdrive ainda dependem de sua evidência específica.

BrowserAct encontrou desafio persistente na Cloudflare; a sessão foi encerrada. O Edge existente chegou à tela de login Cloudflare sem sessão autenticada; a aba de controle foi encerrada. O acesso CLI continua disponível, mas não prova billing. Nenhum recurso oneroso ou DNS foi criado. O workflow `deploy-student-portal.yml` contém neste estágio somente o gate SQL nativo; não executa publicação até os recursos/planos e a ordem Worker→Pages serem comprovados.
